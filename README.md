---

Systems engineer obsessed with the gap between high-level abstractions and the metal underneath. I spend most of my time reading about database internals — Turso's architecture, SQLite's VDBE, how query planners actually make decisions. Right now I'm building what I think is missing: an LLVM-style compilation backend for relational databases where you write standard SQL (Postgres dialect, MySQL dialect, whatever) and it compiles down to a common intermediate representation. The execution layer can then target either an in-process file-based engine (like SQLite) or a daemon-based server model (like Postgres/MySQL) — same query, different deployment topology. I care about making database engines composable instead of monolithic.

**Languages:** Go · C · C++ · Rust . Python · Bash · TypeScript

**Systems:** Linux · Docker · Kubernetes · AWS · Terraform
